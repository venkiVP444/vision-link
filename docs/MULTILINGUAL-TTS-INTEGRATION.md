## 1. Architecture & Routing Layer

The application routes speech synthesis transparently through a unified React Native interface while dispatching to optimized native engines:

```text
React Native (Settings / Detection / Navigation)
                   ↓
         ttsService.speak(text)
                   ↓
          translateText(text, lang)
                   ↓
           TTSModule (Android)
         /          |          \
        /           |           \
     ha-NG        en-GB       ar / hi-IN
       ↓            ↓              ↓
PiperHausaEngine PiperEnglishEngine Android System TTS
 (Malama Asabe)  (Jenny Dioco)    (Locale ar / hi-IN)
       ↓            ↓              ↓
 AudioTrack     AudioTrack    AudioTrack
 (22.05 kHz)   (22.05 kHz)     (System)
```

All engines share identical lifecycle events:
* `onTTSStart`: Sent as soon as audio starts playback
* `onTTSDone`: Sent upon completion of audio rendering
* `onTTSError`: Sent if synthesis or audio output encounters an error

## 2. Voice Engines in Detail

### English (`en-GB`) — Jenny Dioco (Piper Neural)
* **Model Artifact**: `en_GB-jenny_dioco-medium.onnx` (63,201,294 bytes / ~60.2 MB)
* **Configuration**: `model.onnx.json` (sample rate 22,050 Hz, 154 phonemes, espeak phoneme type)
* **Phonemizer Strategy**: `words.json` token dictionary pre-computed for core Vision-Link vocabulary (107 obstacle, navigation, and feedback terms). Fallback to UK system TTS if an unmapped arbitrary word is encountered.
* **DSP Processing**: Custom Biquad DSP with 85 Hz high-pass filter, 3,500 Hz speech presence boost (+2.0 dB), and peak limiter to -1.0 dBFS.
* **Audio Track**: 22.05 kHz 16-bit mono PCM via `AudioTrack(USAGE_ASSISTANT)`.
* **License**: CC BY-SA 4.0 (Dioco / Rhasspy Piper project).

### Hausa (`ha-NG`) — Malama Asabe F4 (Piper Neural) [PRESERVED UNCHANGED]
* **Model Artifact**: `offline_tts/hausa/model.onnx` (73.5 MB)
* **Configuration**: Speaker ID 3 (F4 Malama Asabe), sample rate 22,050 Hz, 42 character/token mappings.
* **Status**: Untouched and 100% preserved. Validated on physical device.
* **Orthography**: Preserves all authentic Hausa hooked characters (`ƙ`, `ɗ`, `ɓ`, `ƴ`).

### Arabic (`ar`) — Nabra-82M Blocker Analysis & System Routing
* **Candidate**: Nabra-82M (`model.int8.onnx`, 79.3 MB, OCI-2.0-Commercial license).
* **Technical Blocker**:
  1. Nabra-82M requires `input_ids` generated by an Arabic G2P phonemizer (`espeak-ng` Arabic binary) and a `voices.bin` style vector.
  2. `com.microsoft.onnxruntime:onnxruntime-android:1.20.0` only runs ONNX graph inference and does **not** bundle a C++ phonemizer.
  3. Shipping Nabra-82M requires `sherpa-onnx-core` AAR (+22 MB native `.so` libraries for arm64/v7a) or custom native C++ JNI phonemization bindings.
* **Resolution**: Per guidelines, Vision-Link **does not fake** Nabra-82M. It routes `ar` through Android system `TextToSpeech` with `Locale.forLanguageTag("ar")` while documenting the exact blocker.
* **POCO C75 Finding**: The factory Google TTS engine on the POCO C75 device does not have the Arabic voice data pre-downloaded, causing system TTS to return `Speech Failed` until the user downloads the language in Android Settings $\to$ Accessibility $\to$ Text-to-speech $\to$ Google TTS voice data.

### Hindi (`hi-IN`) — Android System Hindi Female Voice
* **Configuration**: `Locale.forLanguageTag("hi-IN")` via Android platform `TextToSpeech`.
* **POCO C75 Finding**: On the test POCO C75 unit in airplane mode / without pre-downloaded offline Hindi voice data, Google TTS reported `Speech Failed on utterance`. To use Hindi offline, the device must download the offline voice pack via Android system settings.
